## 延迟实测及边界

同一 Mac mini、同一上游真实目录/关键词，Node HTTP或Ego resource timing；这些是样本，不是所有网络环境的保证。

| 场景 | V2 | V3 |
| --- | --- | --- |
| 真人目录首次 | 8172ms | 浏览器首次292ms |
| 其他分类/四类热榜首次 | 未测 | 153–210ms |
| 搜索同一关键词首次 | App优先5037ms、4条 | 官网直连138ms、10条 |
| 剧集详情首次/缓存 | 683/3ms | 616/2ms |
| 演员榜首次 | 新增功能，继承代理时8255ms | 受检直连1436ms |
| 演员主页/作品列表首次 | 未测 | 2135/403ms |
| 播放首次，包含独立设备及媒体准备 | 未作同条件对照 | 3586ms，随后实际静音播放 |
| 下一集预载/切集接口 | 无 | 841/2ms，第二集实际播放 |

旧目录没有启用已有的可信官网DNS路径；搜索先走App接口，并继承HTTP代理，失败后还会串行回退。现在使用受公网地址检查的官网直连，App仅备用。演员和弹幕分别注入受检直连，不修改机器全局代理。列表/搜索的Web路径与App路径内容可能不同，不能把两者结果条数当成完全同一响应的网络基准。

增加有界服务端缓存、在途读取合并以及页面缓存，失败不缓存。目录/搜索2分钟、详情5分钟。缓存可能短暂保留旧内容，过期后用户动作重新读取；无后台刷新轮询。Server-Timing返回应用总耗时；它包括上游等待，不代表纯CPU时间。

播放取源仍使用原注册设备与签名链路；首次加载包含模型解析、CDN媒体头与客户端解码，不能与列表JSON读取混为一谈。下一集有界预载降低切集等待，解码和网络缓冲仍有成本。
